## Комп'ютерний практикум №5: Створення методів, автоматична генерація даних для усіх класів, юніт тестування

### Завдання

До коду комп’ютерного практикуму №4 додати код для:

- розрахунку обчислювальної властивості;
- автоматичної генерації даних для усіх класів;
- юніт тестування:
  - створення об’єктів;
  - унікальних, обов’язкових властивостей;
  - заповнення відношень;
  - видалення об’єктів, які містять відношення.

Всі тести мають успішно виконатися.
Усі властивості та методи повинні мати сенс.

#### 1. Автоматична генерація даних для всіх класів

Створено клас `Transport.DataGenerator` з методом `GenerateAll()`, який автоматично генерує тестові дані для всіх класів системи:

**Методи генерації**:

- `GenerateOwners(count)` — генерує власників з унікальними ID, іменами, email та телефонами
- `GenerateVehicles(count)` — генерує автомобілі, мотоцикли та вантажівки з:
  - Випадковими марками та моделями з готових списків
  - Унікальними VIN-кодами
  - Двигунами з різними характеристиками
  - Призначеними власниками
  - Колекціями (пасажири для автомобілів, спорядження для мотоциклів)
- `GenerateServiceRecords(count)` — генерує записи обслуговування для транспортних засобів
- `GenerateCargoItems(count)` — генерує вантаж для вантажівок з перевіркою вантажопідйомності

**Використання**:

```objectscript
Do ##class(Transport.DataGenerator).GenerateAll(5)
```

**Особливості**:

- Генерація унікальних VIN-кодів (до 17 символів)
- Автоматичне призначення власників транспортним засобам
- Перевірка вантажопідйомності при додаванні вантажу
- Валідні дати та числові значення

#### 2. Юніт тестування

Створено клас `Transport.TestSuite` з комплексним набором тестів для всіх аспектів системи:

##### 2.1. Створення об'єктів (7 тестів)

- Створення об'єкта `Owner`
- Створення вбудованого об'єкта `Engine`
- Створення об'єкта `Car`
- Створення об'єкта `Motorcycle`
- Створення об'єкта `Truck`
- Створення об'єкта `ServiceRecord`
- Створення об'єкта `CargoItem`

##### 2.2. Унікальні властивості (2 тести)

- Перевірка унікальності VIN (Vehicle) — тестує, що дублікат VIN відхиляється
- Перевірка унікальності Id (Owner) — тестує, що дублікат Id відхиляється

##### 2.3. Обов'язкові властивості (9 тестів)

- `Vehicle.Brand` — обов'язкове поле
- `Vehicle.Model` — обов'язкове поле
- `Vehicle.VIN` — обов'язкове поле
- `Vehicle.Year` — обов'язкове поле
- `Owner.Name` — обов'язкове поле
- `Owner.Id` — автоматично встановлюється конструктором
- `ServiceRecord.ServiceDate` — обов'язкове поле
- `CargoItem.Name` — обов'язкове поле
- `CargoItem.Weight` — обов'язкове поле

##### 2.4. Заповнення відношень (4 тести)

- Відношення `Vehicle -> Owner` (one-many)
- Відношення `Vehicle -> ServiceRecord` (parent-children)
- Відношення `Truck -> CargoItem` (parent-children)
- Вбудований об'єкт `Vehicle -> Engine`

##### 2.5. Видалення об'єктів з відношеннями (3 тести)

- Видалення `Vehicle` з `ServiceRecord` (каскадне видалення children)
- Видалення `Truck` з `CargoItem` (каскадне видалення children)
- Видалення `Owner` з `Vehicle` (не каскадне, транспорт залишається)

##### 2.6. Обчислювані властивості (2 тести)

- Обчислювана властивість `Age` — перевірка правильності розрахунку
- Обчислювана властивість `FullName` — перевірка форматування

**Запуск тестів**:

```objectscript
Do ##class(Transport.TestSuite).RunAllTests()
```

### Створені файли

1. **Transport/DataGenerator.cls** — клас для автоматичної генерації тестових даних
2. **Transport/TestSuite.cls** — клас з комплексним набором юніт-тестів
