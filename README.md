## Лабораторна робота №8 - Створення документів предметної області в MongoDB, виконання звернень та обробка даних

### Завдання

Створити БД та колекції в СУБД MongoDB на базі діаграми класів з
комп’ютерного практикуму №3. Використати вбудовану модель для відображення
відношення parent-children та вбудованого об’єкту. Використати нормалізовану
модель для відображення відношення one-many. Для відображення властивостей та
зв’язків між об’єктами використовувати здоровий глузд.
Створити по 4 документи в кожній колекції. Створити програму
використовуючи будь-який драйвер для підключення до СУБД MongoDB яка:

- виведе усі документи колекцій;
- реалізує запит ключ-значення з мінімум двома умовами;
- реалізує агрегацію з мінімум 4 етапами (обов’язково включити етапи
  lookup та group).
  Усі колекції, документи та запити мають мати сенс.

## Встановлення та запуск

1. Переконайтеся, що MongoDB запущений локально:

   ```bash
   mongod
   ```

2. Збірка проекту:

   ```bash
   mvn clean compile
   ```

3. Запуск програми:

   ```bash
   mvn exec:java
   ```

## Функціональність

Програма виконує наступні завдання:

1. **Ініціалізація бази даних**:

   - Створює колекції: `owners`, `vehicles`, `serviceRecords`
   - Додає по 4 документи в колекцію `owners`
   - Додає 12 документів в колекцію `vehicles` (4 автомобілі, 4 мотоцикли, 4 вантажівки)
   - Додає 16 документів в колекцію `serviceRecords`

2. **Виведення всіх документів**:

   - Виводить всі документи з кожної колекції

3. **Запит ключ-значення**:

   - Знаходить автомобілі, випущені після 2020 року, з двигуном потужністю більше 200 к.с.

4. **Агрегація**:
   - Використовує 7 етапів агрегації (включаючи `$lookup` та `$group`)
   - Для кожного власника підраховує:
     - Загальну вартість сервісних обслуговувань
     - Середній пробіг транспортних засобів
     - Кількість транспортних засобів

### Що було зроблено

#### 1. Створено базу даних MongoDB з трьома колекціями:

- **owners** - 4 документа (власники транспортних засобів)
- **vehicles** - 12 документів (4 автомобілі, 4 мотоцикли, 4 вантажівки)
- **serviceRecords** - 16 документів (сервісні записи)

#### 2. Реалізовано зв'язки між колекціями

##### Таблиця зв'язків між колекціями:

| Зв'язок                            | Тип зв'язку              | Колекція/Поле                                |
| ---------------------------------- | ------------------------ | -------------------------------------------- |
| **Vehicle ↔ Owner**                | Один до багатьох (1..\*) | `vehicles.ownerId` → `owners.ownerId`        |
| **Vehicle ↔ Engine**               | Один до одного (1..1)    | `vehicles.engine`                            |
| **Vehicle ↔ ServiceRecord**        | Один до багатьох (1..\*) | `serviceRecords.vehicleVin` → `vehicles.vin` |
| **Truck ↔ CargItem**               | Один до багатьох (1..\*) | `vehicles.cargo[]`                           |
| **Vehicle → Car/Motorcycle/Truck** | Наслідування             | `vehicles.vehicleType`                       |

#### 3. Реалізовано Java програму з наступним функціоналом:

- **Виведення всіх документів** з усіх колекцій
- **Запит ключ-значення** з трьома умовами:
  - `vehicleType == "Car"`
  - `year > 2020`
  - `engine.horsePower > 200`
- **Агрегація з 7 етапами**:
  - `$lookup` (2 рази) - з'єднання з колекціями vehicles та owners
  - `$unwind` (2 рази) - розгортання масивів
  - `$group` - групування по власнику з підрахунком загальної вартості, середнього пробігу та кількості
  - `$project` - формування фінального вигляду
  - `$sort` - сортування за загальною вартістю

#### 4. Використані підходи до моделювання:

- **Вбудована модель (Embedded)**:
  - Engine в Vehicle (один-до-одного)
  - CargItem в Truck (один-до-багатьох, parent-children)
- **Нормалізована модель (Referenced)**:
  - Owner ↔ Vehicle (один-до-багатьох)
  - ServiceRecord ↔ Vehicle (один-до-багатьох)

### Висновки

Проект демонструє правильне використання різних моделей даних MongoDB:

- Вбудовані об'єкти використані для тісно пов'язаних даних (Engine, CargItem)
- Нормалізовані посилання використані для зв'язків один-до-багатьох з можливістю незалежного існування сутностей (Owner, ServiceRecord)
